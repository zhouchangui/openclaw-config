# HEARTBEAT_STANDARD.md - 多智能体 Heartbeat / Cron 统一规范

## 目标

本规范用于统一所有 OpenClaw 智能体的定时巡检、提醒和告警行为，避免各智能体各自为政、输出风格不一致、调度职责混乱。

适用范围：
- 当前已存在的智能体
- 后续新建的智能体
- 所有通过 heartbeat 或 cron 触发的定时任务

---

## 总原则

1. **统一入口，分离职责**
   - heartbeat 是统一的定时唤醒/巡检机制。
   - 每个智能体必须在自己的 `HEARTBEAT.md` 中定义收到 heartbeat 后的处理逻辑。
   - 不允许把复杂业务逻辑硬编码到调度 payload 中。

2. **Heartbeat 与 Cron 分层**
   - **Heartbeat**：用于巡检、状态确认、遗漏检测、轻量提醒、异常发现。
   - **Cron**：用于精确定时、强时效、明确产出型任务（如固定时间发报告、固定时间生成内容、固定时间发布）。
   - 如果一个任务本质是“必须在某一时刻执行某个明确动作”，优先用 cron。
   - 如果一个任务本质是“周期性看看有没有异常/遗漏/需要提醒的事”，优先用 heartbeat。

3. **默认安静，异常唤醒**
   - 没有异常、没有遗漏、没有明确待办时，优先回复 `HEARTBEAT_OK`。
   - 不允许为了“显得在工作”而输出无意义检查报告。

4. **输出分级统一**
   - 无异常：`HEARTBEAT_OK`
   - 普通事项：简短提醒，说明问题、影响、建议动作
   - 严重异常：直接告警，优先说明风险和建议处理步骤

5. **各智能体必须自洽**
   - 每个智能体只能处理自己职责范围内的 heartbeat 事项。
   - 如果需要跨域信息，必须从明确的数据源读取，不得凭空推断。

---

## 每个智能体必须提供的 HEARTBEAT.md 结构

所有智能体的 `HEARTBEAT.md` 应尽量包含以下 6 段：

1. `## 目标`
   - 说明 heartbeat 的职责边界

2. `## 每次 Heartbeat 执行`
   - 收到 heartbeat 默认执行哪些检查

3. `## 安静条件`
   - 什么情况下直接回复 `HEARTBEAT_OK`

4. `## 普通提醒条件`
   - 什么情况下提醒用户，但不属于严重事故

5. `## 立即告警条件`
   - 什么情况下必须立即通知用户

6. `## 输出规则`
   - 明确 `HEARTBEAT_OK` / 普通提醒 / 严重告警 的格式偏好

---

## Heartbeat 适用场景

适合 heartbeat 的任务：
- 系统健康巡检
- 日志异常发现
- 渠道连通性检查
- 今日任务或文档是否遗漏
- 报告或产出物是否缺失
- 轻量级待办提醒
- 长周期经验整理提醒

不适合 heartbeat 的任务：
- 必须在固定时间点执行的报告生成
- 必须在固定时间点发送的消息或推送
- 依赖明确时刻窗口的发布动作
- 计算量大、耗时长、步骤复杂的完整工作流

这些任务优先使用 cron 或显式触发命令。

---

## Cron 适用场景

适合 cron 的任务：
- 每日 08:30 固定生成早报
- 每晚 22:00 固定生成日报
- 每周一 09:00 固定执行周报
- 需要在固定时刻触发的发布、发送、汇总、归档动作

Cron payload 规则：
- 只写“调用哪个能力、完成什么结果、返回什么格式”
- 不嵌入复杂 shell 实现细节
- 具体实现放在对应工作流或 skill 文档中

## 现阶段建议分层

### 适合 heartbeat 主导
- `ops-admin`
- `dingding-assistant`

### heartbeat + cron 混合
- `investment-advisor`
  - cron 负责准点生成报告
  - heartbeat 负责检查报告是否漏发、接口是否异常

### 适合 cron 主导、heartbeat 仅兜底
- `wechat-lobster`
  - cron 负责精确选题、发布、周计划动作
  - heartbeat 仅做轻量巡检或兜底确认

---

## 新增智能体接入要求

以后新增智能体时，必须遵守以下规则：

1. 创建工作区时同步创建 `HEARTBEAT.md`
2. 在 `AGENTS.md` 的 Session Startup 中加入对本规范的读取要求
3. 明确该智能体属于：
   - heartbeat 主导
   - cron 主导
   - heartbeat + cron 混合
4. 不得省略安静条件和告警条件
5. 不得把 heartbeat 写成泛泛而谈的“看看有没有事”

---

## 推荐模板

```md
# HEARTBEAT.md - <Agent 名称>巡检清单

## 目标
说明 heartbeat 负责什么，不负责什么。

## 每次 Heartbeat 执行
- 检查项 1
- 检查项 2
- 检查项 3

## 安静条件
以下情况回复 `HEARTBEAT_OK`：
- 条件 1
- 条件 2

## 普通提醒条件
以下情况主动提醒用户：
- 条件 1
- 条件 2

## 立即告警条件
以下情况必须立即通知用户：
- 条件 1
- 条件 2

## 输出规则
- 无异常：回复 `HEARTBEAT_OK`
- 普通事项：简洁说明问题、影响、建议动作
- 严重异常：直接告警，并优先说明风险
```

---

## 执行要求

- 所有现有智能体应逐步对齐本规范
- 对现有智能体的 `HEARTBEAT.md` 做局部差异化保留，但结构必须统一
- 后续新增智能体默认以本规范为 heartbeat / cron 设计基线
