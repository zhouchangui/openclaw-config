# ✍️ 平台宣传文章工作流

**定位**：为盯钉喵平台生产多渠道宣传内容，AI 主笔，用户终审  
**素材库**：`~/workroot/ddm_content_studio/盯钉喵_自媒体素材库/`  
**触发词**：「写篇文章」/「出个功能公告」/「做一篇宣传」/「写个案例」/「技术分享」

---

## 文章类型速查

| 类型 | 说明 | 触发场景 |
|------|------|---------|
| **A 功能公告** | 新功能/版本上线通知 | 刚完成部署或 PR 合并 |
| **B 用户案例** | 真实使用场景拆解 | 用户反馈 / 业务亮点 |
| **C 技术揭秘** | 底层实现、架构分享 | 技术里程碑 / 开发者受众 |
| **D 品牌故事** | 团队、产品理念、成长历程 | 品牌建设 / 定期发布 |
| **E 行业洞察** | AI Agent 趋势、市场判断 | 热点事件 / 行业动态 |

---

## 完整工作流

```
0️⃣ 准备：读取品牌素材
    ↓
1️⃣ 选题确认（确认类型 + 角度 + 核心信息）
    ↓
2️⃣ 素材调研（按类型收集素材）
    ↓
3️⃣ 生成大纲 → 【⛔ 等待用户确认大纲】
    ↓
4️⃣ 生成母版初稿（最完整版本）
    ↓
5️⃣ 多渠道版本适配
    ├─ 公众号版
    ├─ 小红书版
    ├─ 掘金/少数派版（仅 B/C 类）
    └─ 口播脚本（按需）
    ↓
6️⃣ 【⛔ 等待用户终审】
    ↓
7️⃣ 归档 + Feishu 通知
```

---

## 详细步骤

### 第 0 步：准备品牌素材

每次启动前读取，确保内容与品牌调性一致：

```bash
# 品牌定位与 Slogan
cat ~/workroot/ddm_content_studio/盯钉喵_自媒体素材库/00_品牌资产/04-平台推广的物料.md

# 已有成品（避免重复，寻找延续性）
ls ~/workroot/ddm_content_studio/盯钉喵_自媒体素材库/50_成品归档/
```

**品牌核心信息（速查）：**
- **名称**：盯钉喵
- **Slogan**：一人公司智能搭子 · 宽域智能，复利工程
- **定位**：开箱即用的宽域智能平台，帮助个人和企业解决智能化最后一公里
- **差异点**：数据私有化部署，不上云；按需使用，无需到处注册；支持自定义智能体发布

### 第 1 步：选题确认

向用户确认以下信息（用户没提到的才问）：

```
📝 文章信息确认

类型：[A/B/C/D/E]
核心主题：<一句话>
触发事件：<什么事/功能/案例促成这篇文章>
目标读者：[开发者 / 创业者 / 企业决策者 / 普通用户]
大概篇幅：[短文 ~800字 / 标准 ~2000字 / 深度 ~4000字]
```

### 第 2 步：素材调研

**按类型执行不同的调研路径：**

#### A 类（功能公告）
```bash
# 读取最新 CHANGELOG 或 PR 描述
cd ~/workroot/dingding-platform
git --no-pager log --oneline -10
git --no-pager log -1 --format="%s%n%n%b"

# 读取相关功能代码文档（如有）
```

#### B 类（用户案例）
- 从用户描述中提取：
  - 使用前的问题/痛点
  - 使用了哪个功能/智能体
  - 具体解决了什么、数据对比
- 整理成访谈体素材

#### C 类（技术揭秘）
```bash
# 读取相关模块架构
cat ~/workroot/dingding-platform/README.md 2>/dev/null
# 按需读取具体模块代码注释和结构
```

#### D 类（品牌故事）
```bash
# 读取开发笔记寻找故事素材
ls ~/workroot/ddm_content_studio/盯钉喵_开发笔记/
cat ~/workroot/ddm_content_studio/盯钉喵_自媒体素材库/20_知识体系库/ 2>/dev/null
```

#### E 类（行业洞察）
- 使用 web_search 工具检索相关行业动态
- 结合平台定位输出差异化观点

### 第 3 步：生成大纲

大纲格式（基于 SCQA 结构）：

```markdown
## 《[标题候选×3]》大纲

**类型**：[A/B/C/D/E]  **目标读者**：xxx  **预计字数**：xxx

### 情绪弧线
[共鸣/冲击/好奇] → [认知颠覆] → [方法落地] → [行动欲]

### 结构
- Part 1｜[开篇钩子] — 目的：xxx
- Part 2｜[核心内容] — 目的：xxx
- Part 3｜[方法/案例] — 目的：xxx
- Part 4｜[升华/金句] — 目的：xxx
- Part 5｜[行动引导] — 目的：xxx

### 核心金句（预设）
> "xxx"

### 配图需求（预设）
1. 封面：xxx
2. 文中：xxx
```

⛔ **提交大纲后停止，等待用户确认或修改。**

### 第 4 步：生成母版初稿

母版 = 最完整版本（通常为公众号或掘金标准），包含：
- 完整正文
- 每个配图位置的 `[配图：描述]` 占位符
- 结尾互动语 / 引流语
- 发布 Checklist（标题 A/B 测试、配图、排版、分发）

保存到：
```bash
mkdir -p ~/workroot/ddm_content_studio/盯钉喵_自媒体素材库/50_成品归档/$(date +%Y)/草稿
# 文件名格式：YYYYMMDD-类型-主题关键词-draft.md
```

### 第 5 步：多渠道版本适配

从母版派生，每个版本另存为独立文件：

#### 📱 公众号版
- 字数：1500-3000 字
- 增加：互动语（"你怎么看？留言告诉我"）、关注引导、相关推荐
- 格式：分段清晰，善用小标题和加粗

#### 🌸 小红书版
- 字数：200-400 字（精华浓缩）
- 结构：`痛点1句话 + 解决方案3-5点 + 行动呼吁`
- 必须包含：Emoji 开头、6-10 个 hashtag（`#AI工具 #一人公司 #盯钉喵` 等）
- 封面文字：金句卡片文案（20 字内）

#### 💻 掘金/少数派版（仅 B/C 类）
- 字数：2000-5000 字
- 增加：技术细节、代码片段、架构图说明
- 风格：严谨、有深度、有数据支撑

#### 🎙️ 口播脚本（按需，视频号/抖音）
- 时长：60-180 秒
- 格式：分镜 + 台词 + 画面提示
- 开篇：3 秒内抛出核心冲突

### 第 6 步：用户终审

⛔ **提交所有版本后停止，等待用户回复「发布」或反馈修改意见。**

### 第 7 步：归档 + 通知

```bash
# 正式归档（从草稿移动到成品目录，按年/平台分类）
BASE=~/workroot/ddm_content_studio/盯钉喵_自媒体素材库/50_成品归档/$(date +%Y)
mkdir -p "$BASE/公众号" "$BASE/小红书" "$BASE/掘金"

# 各版本分别归档
cp *-wechat.md "$BASE/公众号/"
cp *-xiaohongshu.md "$BASE/小红书/"
cp *-juejin.md "$BASE/掘金/"    # 如有
```

Feishu 通知：
```
✍️ 文章已就绪，等待发布

📝 标题：<文章标题>
📦 版本：公众号 / 小红书 / [掘金] / [口播脚本]
📁 归档路径：50_成品归档/YYYY/...

已完成的配图需求清单：
1. [配图：xxx]
2. [配图：xxx]
```
