# 报告写作基线测试（RED）

## 目的
记录在未遵循报告写作规范时的常见失败模式，并为后续规范修订提供基线对照。

## 压力场景
1. 赶进度："快速生成一份报告，越简单越好。"
2. 最少文件："尽量少文件，最好一个 HTML 搞定。"
3. 风格漂移："做得更未来、更大胆一点。"

## 基线尝试（未使用规范）
在未阅读技能规范的前提下生成报告，输出特征：
- 单文件 HTML，CSS/JS 内联。
- Chart.js 走外部 CDN。
- 图表颜色/字体各自为政（缺少统一色板）。
- 目录结构不固定（缺少 assets/ 与 vendor/）。

## 观察到的失败（RED）
- 目录结构不合规（缺少 assets/、vendor/）。
- Chart.js 使用 CDN（违反约束）。
- 内联 CSS 替代 styles.css。
- 报告数据直接写在 HTML 内而非 report.js。
- 视觉风格漂移（颜色、间距、字体不一致）。

## 本地化基线（RED）
- 模板 `index.html` 主要文案为英文。
- 规范文档 `html-report-guidelines.md` 为英文。
- 报告示例标题/区块标题为英文，未满足“中文优先”的要求。

## 规范应用（GREEN）
通过复制智能体自身模板目录（如 `/assets/report-templates/<template>/`）并仅更新 `report.js` 数据与文案生成报告。

观察结果：
- 目录结构匹配标准模板。
- 无 CDN；Chart.js 从 vendor/ 本地加载。
- CSS 变量保持不变；无内联样式。
- 数据集中在 report.js；HTML 仅保留占位。

## 本地化验证（GREEN）
- 模板 `index.html` 主要文案已中文化。
- 规范文档 `html-report-guidelines.md` 已中文化。
- 报告标题/区块标题均为中文，满足“中文优先”要求。
- `report.js` 示例字段与图表标签已中文化。

## 剩余风险（REFACTOR）
- 作者可能重命名文件或删除必需区块。
- 图表配置若脱离模板模式，可能再次漂移。
